# Multithreaded Download Manager — багатопотоковий менеджер завантажень

**Орієнтир:** 3 тижні (тижні 3–5)

## Мета
Освоїти координацію потоків, скасування, відновлення завантажень і перевірку мережевих відповідей.

## Функціональні вимоги
- Черга HTTP/HTTPS URL, ліміт одночасних завантажень, прогрес і швидкість для кожного файлу.
- Пауза, продовження, скасування; збереження стану черги й тимчасових `.part`-файлів.
- Повторні спроби з лімітом і затримкою; тайм-аути; перевірка HTTP-статусу й TLS-сертифіката.
- Відновлення через Range лише за підтримки сервера. Перевіряти `Content-Range` та `ETag`/`Last-Modified`; якщо ресурс змінився — починати заново.

## Поведінка (прийняті рішення)
- **Інтерфейс.** Консольний цикл команд; завантаження йдуть у фоні, поки користувач вводить команди:
  `add <url> [файл]`, `list`, `pause <id>`, `resume <id>`, `cancel <id>`, `help`, `exit`.
  Після ядра — GUI на Qt Widgets як окремий шар UI поверх того самого ядра.
- **Прогрес.** На запит: команда `list` показує для кожної задачі стан, завантажено / всього,
  відсоток і швидкість. У консолі прогрес живцем не перемальовується.
- **Куди зберігати.** Тека за замовчуванням — `./downloads` (створюється за потреби).
  Ім'я файлу береться з останнього сегмента шляху URL (без query і fragment).
  Якщо файл з таким ім'ям уже існує, додається суфікс: `name (1).ext`, `name (2).ext`, ...
  Якщо в черзі вже є задача з тим самим цільовим файлом, `add` повертає помилку.
- **Ліміти за замовчуванням.** 3 одночасні завантаження; 5 спроб на задачу; затримка між
  спробами експоненційна: 1 → 2 → 4 → … с, не більше 30 с.
- **Скасування** видаляє `.part`. **Пауза** його зберігає для подальшого відновлення.

## Технології
libcurl, `std::jthread`, `std::stop_token`, mutex, condition_variable; JSON для стану черги. Кожен робочий потік — власний curl easy handle.

## План
1. Послідовне завантаження одного файлу в `.part` з перевіркою помилок і фінальним перейменуванням.
2. Черга та обмежений пул працівників. Стани задачі та їх синхронізація.
3. Прогрес, тайм-аути, повторні спроби, скасування через callback бібліотеки.
4. Пауза й збереження стану. Range та обробка сервера, що повернув 200 замість 206.
5. Перевірка на локальному тестовому HTTP-сервері: обрив, 404, зміна ресурсу, відсутність Range.

## Критерій готовності
- [ ] Після відновлення файл побайтово збігається з оригіналом
- [ ] Ліміт паралельності дотримано
- [ ] Завершення програми зупиняє й приєднує всі потоки

## Розширення
Сегментоване завантаження одного файлу після перевірки підтримки Range.
